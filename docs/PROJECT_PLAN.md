# 项目设计：电商用户增长与补贴策略评估

目标岗位：抖音电商用户增长数据分析实习。独立作品集，非抖音任职经历。

## 业务问题与 JD 对应

| JD | 项目问题 | 产出 |
|---|---|---|
| 构建增长指标与模型 | 活跃增长是否转化为购买增长？ | DAU、购买用户、转化、可观测 cohort 留存、增长拆解 |
| 人货场刻画 | 哪类用户、品类、场景值得优先验证？ | 模拟实验分层数据、公开日志描述指标、机会清单 |
| 补贴、投放效果与 ROI | 发券带来额外购买还是补贴自然购买？ | ITT、CUPED、T-Learner、IPW策略评估、净利润区间 |
| 熟练使用 Hive | 明细日志如何形成可复用指标？ | Hive 清洗、严格有序漏斗、成熟 cohort 留存 SQL |
| 协同落地迭代 | 怎么让分析转化为可验证策略？ | 实验方案、埋点契约、上线验收清单（设计产物） |

## 数据边界

1. 默认运行产生60,000名**合成用户**，分组前包含行为、品类和模拟场景，分组后包含购买、毛利、补贴成本。模拟短视频/直播/商城不代表真实抖音业务分布。
2. 可自行下载天池 UserBehavior 的五列 CSV，用 `--userbehavior` 单独计算每日用户与行为量。没有订单金额，不能计算真实GMV、ROI或RFM中的金额；没有场景或随机补贴分组，不能估计真实补贴效果。
3. 真实日志与模拟实验不做用户关联。公开日志中的首次出现只能叫首次观测，不能认定平台新用户。
   Python适配器保留原始事件次数、按行为去重用户；Hive模板另按五字段完全相同去重，使用时应根据日志重复语义统一口径。
4. 可以后续用 Criteo 随机广告实验数据验证 Uplift 方法；当前版本不含其数据或结果，广告实验也不能直接当作补贴实验。

## 增长逻辑与指标口径

购买用户数 = 活跃用户数 × 活跃用户购买率。同口径增长差可拆成活跃变化、转化变化及交互项。真实业务还需按注册新客、存量、流失召回拆解，公开日志无法完成注册口径。

- 用户指标：DAU、购买用户、D1/D7活跃留存；明确分母、时区、观察窗口、去重粒度。
- 转化指标：用户－商品－日的浏览→加购→购买有序漏斗，直接购买和跨日路径另行分析；不能用行为总量比值声称路径转化。
- 人：分组前浏览/加购/购买次数、距最近活跃天数；模拟新用户标签。
- 货：品类分层；真实价格带、库存、退款率需接入商品和订单数据。
- 场：模拟场景分层；真实场景分析需场景曝光、点击、商品访问和订单归因埋点。
- 财务指标：增量毛利、补贴核销成本、增量净利润与净ROI。默认模拟毛利率25%，券额8元，无履约或退款成本，正式决策需补齐。

## 可复现实验与策略评估

- 用户级50/50随机分组；发券资格决定 treatment，不能以领券、核销代替分组。整体 ITT 为主要因果效应。
- 主指标购买转化；经济指标增量净利润；退款、投诉、后续留存作为真实上线护栏（当前合成数据未覆盖）。
- 检查 SRM；报告 Welch 差值置信区间、p-value、样本量/MDE；CUPED 只用分组前购买次数。
- 按用户拆成60%训练、20%验证、20%测试。T-Learner 用两棵随机森林估计两组购买概率差。
- 在验证集的不发券、10%到50%比例中选择估计净利润最高的策略，冻结后在独立测试集评估；保留不发券选项，避免强行使用负收益策略。
- 比较相同触达比例的随机、自然转化评分、Uplift 策略；全量发券作参照。相同触达不等于相同核销预算。
- IPW/HT使用已知实验分组概率，估计相对不发券的增量转化、毛利及成本。置信区间为固定模型和策略条件下的逐用户bootstrap。
- 预算约束扩展：用验证集预估成本和收益，确定阈值，在实际预算内重新随机验证；本版本没有宣称完成预算最优分配。

## 机会如何转成落地建议

探索假设：高加购、未购买用户可能更受补贴影响。先检查分层增量效应和样本量，再设计预注册分层实验；不能从模拟生成规则推断现实用户规律。

提交给产品：目标用户定义、发券阈值、券额、预算、频控与停止规则。
提交给算法：分组前特征快照、训练窗口、特征契约、Uplift评分与漂移监控。
提交给研发：user_id、assignment_id、assigned_at、scene_id、券领取/核销、订单支付/退款事件；用户稳定分组、互斥实验、重复触达去重。
验收：分组与曝光一致性、SRM、成本对账、退款成熟期、预先确定观察窗与停止规则。上述为协作方案，不是已经与真实团队完成的上线经历。
