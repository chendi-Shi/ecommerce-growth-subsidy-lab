# 简历项目描述

## 可使用的基础版本

**电商用户增长与补贴策略评估｜独立项目（合成数据）**  
技术：Python、Pandas、SciPy、scikit-learn、Hive SQL（模板）

- 围绕电商用户增长搭建活跃、购买转化、有序漏斗及cohort留存指标口径，编写Hive SQL清洗与聚合模板，支持公开用户行为日志分析。
- 基于模拟用户实验数据，从分组前行为、商品品类及短视频/直播/商城模拟场景刻画人货场，形成高意向未购买用户的补贴验证假设。
- 设计用户级随机补贴实验，完成SRM、ITT、CUPED、样本量及置信区间分析，以增量毛利、补贴成本和净ROI评估策略经济性。
- 构建T-Learner估计用户增量购买概率，通过训练/验证/测试隔离，对比随机、转化评分与Uplift定向策略，输出策略评估报告、埋点契约和实验验收方案。

## 实测结果版本

**电商用户增长与补贴策略评估｜独立项目（合成数据）**  
Python / Pandas / SciPy / scikit-learn / Hive SQL（模板）

- 围绕电商增长构建活跃、购买转化、有序漏斗与cohort留存指标体系，编写Hive清洗及聚合SQL，明确去重粒度、事件顺序和留存观察窗口。
- 基于6万合成用户，按分组前行为、品类及模拟消费场景开展人货场分层分析，设计用户级随机发券实验，完成SRM、ITT、CUPED及样本量评估；模拟购买转化差为3.98个百分点，95% CI为[3.53, 4.42]。
- 构建T-Learner估计增量购买概率，按60%/20%/20%隔离训练、策略选择与测试，在1.2万独立测试用户上对比随机、转化评分及Uplift定向策略，采用IPW评估增量毛利、核销成本和净ROI。
- 输出策略报告与产品/算法/研发埋点及验收方案；Uplift策略增量净利润点估计为每名合格用户0.215元，95%区间[-0.014, 0.423]，识别当前盈利证据不足，提出扩大实验或调整券额的后续验证方案。

以上为实际代码运行结果；数据为合成数据，不应写成抖音真实增长或上线收益。简历篇幅紧张时，可删去最后一条的具体利润数值，保留实验结论和策略输出。

## 面试说明

**为什么选择补贴主题？**  JD强调用户增长、补贴和投放效率。本项目研究补贴对购买的增量贡献，区分自然购买倾向与干预后额外购买。

**为什么不用普通购买预测模型决定发券？**  高购买概率用户可能不发券也会买；因此同时比较自然转化排序与两组概率差排序。

**如何避免数据泄漏？**  特征全部来自分组前；购买、收入、补贴和模拟真值不进入模型；先拆用户，再训练、验证选阈值、测试评估。

**为什么不声称真实ROI提升？**  券额、价格和毛利率均为模拟设定，未包含退款与履约成本。评估展示方法能力，真实收益须接入实际财务口径并上线随机验证。

**Hive用了什么？**  编写了清洗、有序漏斗和成熟cohort留存SQL模板，未部署或运行Hive集群。熟悉SQL不等于拥有生产Hive经验，面试应如实说明。

**协同产品/算法/研发怎么体现？**  仓库提供目标人群、特征快照、稳定分组、埋点字段、成本对账及验收要求。它们是项目设计产物，不是已经完成真实团队上线协作的经历。

**现在已经完成了什么？**  以reports/REPORT.md和测试记录为准。公开UserBehavior适配代码可以运行，但未取得完整公开原始数据时，不写“已分析上亿条真实行为”。
