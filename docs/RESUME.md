# 简历项目描述

## 推荐投递版

**电商增长异常诊断与营销投入决策｜独立研究项目**

Python、SQL、Apache Hive、实验分析、因果推断

- 围绕“买家增长、购买金额下降”处理106.7万条真实交易，建立账簿范围、客户结构、商品组合等竞争假设；通过已识别/匿名/退货桥接，发现已识别客户金额下降1.68%时，全体净商品金额实际增长2.34%，修正对整体经营恶化的判断。
- 用比较期之前的消费冻结前1%高购买额客户，定位38人贡献−£3.82万、其余已识别客户+£1.88万；结合客户集合、同SKU与商品组合分解及11个月同比检查，将调查优先级收敛到身份覆盖、大客户订单和海外订单篮子，提出补充数据与验证条件。
- 独立复盘6.4万用户随机营销实验，区分平均触达效果与定向额外优势；固定策略后拆解人群/内容选择，估计每名合格用户增量收入差的95%区间为[−$0.279,$0.267]，进一步建立实施成本门槛与未来验证样本量情景，避免将“不显著”解释为无业务价值。
- 实际执行6.4万行Apache Hive分层指标并完成21项对账；将交易分解恒等式、策略重建校验、数据边界及业务决策备忘录纳入可复现代码与测试，形成面向运营、产品和数据研发的后续验证方案。

## 三条精简版

**电商增长诊断与实验决策｜公开数据独立研究**

- 对106.7万条交易开展竞争假设分析，发现已识别客户金额−1.68%与全体净商品金额+2.34%的口径反转；以前期消费固定大户名单，通过客户集合及商品组合分解定位局部波动，形成分层调查建议。
- 复盘6.4万用户三臂随机营销实验，冻结定向策略并做配对评估；将较宽的收益区间映射到成本门槛和后续样本需求，区分“平均触达有效”“定向有额外优势”和“值得额外投入”。
- 使用SQL/Python实现增长诊断与可复现验证，实际运行Hive完成21项指标对账，交付业务决策备忘录及补贴实验迁移方案。

## 面试讲述重心

先讲一个被证据修正的判断：从已识别客户收入下降，追到全体商品账簿仍增长；再发现少数前期高购买额客户与商品组合足以改变调查重点。讲清为什么这些观察不能直接推出“发券可挽回多少收入”。

实验案例单独讲，不说它验证了UCI客户的策略：原始邮件实验平均有效，但模型定向的额外优势不确定；引入成本门槛后，才知道这个区间能否回答经营问题，以及是否值得继续收集数据。

这是独立研究，未推动真实企业上线或创造已实现补贴收益。时间填写实际投入时间；新增诊断是回顾研究，不宣称预注册。投递前按[面试指南](INTERVIEW_GUIDE.md)复现并讲透相关结果。
