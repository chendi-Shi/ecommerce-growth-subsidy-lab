# 电商增长项目模型白话讲解

这个项目想回答两件事：**生意的变化发生在哪里；营销的钱怎样花才更可能带来额外购买。** 模型只是回答这些问题的工具。读完后，你应该能解释每个工具吃进去什么、算出什么、为什么需要它，以及结果能支持什么决定。

下面先讲直觉，再讲本项目怎么实现。标有“教学例子”的数字是为了手算；标有“项目结果”的数字来自仓库中的真实公开数据分析。第一次阅读可以先跳过代码，只看问题、例子和结论。

仓库有两个独立案例：106.7万条零售交易用于经营诊断；6.4万人的随机邮件实验用于营销效果研究。它们来自不同业务，没有可连接的共同客户ID。我们没有先从零售数据选出客户，再给这些客户做邮件实验。邮件实验也没有真实优惠券核销记录，不能直接写成补贴ROI。

## 先把目标说清楚

把自己想成店长。你面前有两道题。

第一道题是：“这个月买东西的人变多了，购买金额却少了，问题在哪里？”你要检查是不是统计范围变了、重点客户少买了、每单件数少了，或购买转向便宜商品。这部分主要靠SQL、分组比较和数学分解。

第二道题是：“面前有12,800名客户，最多联系2,000人。应该联系谁，给他发男装还是女装内容？”你要关心这次联系能多带来多少消费。联系一个本来就会买的人，可能没有增加任何购买。这部分需要随机实验和增量模型。

```text
零售交易案例
订单明细 → 算清人数和金额 → 检查竞争解释 → 缩小客户和商品调查范围

随机营销案例
随机分组数据 → 检查平均效果 → 预测不同人的增量 → 选择触达规则
                                                      ↓
                           独立数据评估规则 → 对照成本决定是否继续投入
```

每个方法先记一句话：

| 方法 | 用大白话说，它在做什么 |
|---|---|
| SQL和数仓 | 把零散流水整理成可以认真算账的表 |
| RF规则分群 | 按最近买没买、买过几次，给客户贴行为标签 |
| Cohort复购分析 | 给客户足够的观察时间，再看是否回来购买 |
| Shapley分解 | 多个因素一起变化时，把账面差额按规则分清楚 |
| 商品组合分解 | 分清是同样商品卖便宜了，还是便宜商品的购买件数占比提高 |
| 逻辑回归 | 估计一个人本来有多大概率购买 |
| Ridge回归 | 根据用户特征预测消费，同时约束过于激进的系数 |
| 随机森林 | 用许多棵分情况判断的树共同预测 |
| T-Learner | 分别预测发和不发时的消费，再相减 |
| DR-Learner | 用随机实验修正预测误差，构造增量学习目标 |
| DR策略评估 | 用独立实验日志给整套触达规则算成绩 |
| CUPED式调整 | 利用历史信息，尝试减少实验结果里的自然波动 |

## 先理解模型到底在学什么

“模型”可以先理解成一条从数据里学出来的计算规则。把一个人的历史购买信息放进去，它给出一个预测。

**特征**就是预测时已经知道的信息。例如距上次购买多久、过去一年花过多少钱、从什么渠道购买。

**目标或标签**就是训练时希望预测的答案。例如接下来14天是否购买，或者消费多少美元。“预测是否购买”和“预测购买金额”是两项不同任务。

**训练**是利用历史特征和已知答案，调整计算规则，让预测误差尽可能小。**预测**是规则学好以后，对新用户只输入特征，不看未来答案，算出估计值。

**过拟合**可以理解为记住了练习题里的偶然情况。例如某类客户碰巧有两个人大额消费，模型就以为这类人都会大量购买。到了另一批人，规律消失了。

**参数**是训练学到的数，比如回归系数。**超参数**是训练前设置的约束，比如树最多长多深。代码里出现`alpha=100`，不表示模型自动发现100最好；本项目把它作为固定设置。

这个项目没有使用BERT，也没有处理自然语言语义。商品描述用于解释结果，实际预测使用结构化用户特征。

## 把用户信息变成模型能计算的数字

**目标：把每个人统一表示为一排数字，交给后面的模型。**

教学例子中，一个用户的信息可能是：

```text
距上次购买2个月
过去一年消费200美元
买过男装，没买过女装
不是新客户
住在城市地区
从网页渠道购买
```

本项目使用5个数值字段和2个类别字段。`mens`、`womens`表示是否买过对应商品，不是用户性别。

| 输入 | 处理方法 | 为什么处理 |
|---|---|---|
| 距上次购买时间recency | 标准化 | 给数值一个可比较的尺度 |
| 历史消费history | 先log1p，再标准化 | 缩小长尾金额的尺度差距 |
| mens、womens、newbie | 作为数值字段统一标准化 | 与其余数值字段进入同一流水线 |
| 区域类型zip_code | One-hot编码 | 避免给类别编造大小关系 |
| 渠道channel | One-hot编码 | 让模型知道属于哪个渠道 |

One-hot很简单。假设渠道顺序是“多渠道、电话、网页”，那么网页用户变成`[0, 0, 1]`。它只表示类别，没有学习“网页”这个词的含义。

历史消费取`log(1+金额)`。例如原来的100与10,000相差100倍，取对数后数值距离小得多；加1让零消费也能计算。实验后的目标消费`spend`保留美元原值，因为我们最后要算多赚了多少美元。

标准化相当于重新选单位：把“高于训练样本平均值多少”除以训练样本的标准差。训练时记住这套刻度，预测新用户时继续沿用，不能用测试集重新定刻度。

两个类别各有3种时，总共是`5+3+3=11`个输入数字。树本身并不要求标准化，本项目为了复用同一套处理流程也这样做。

代码对应：[feature_frame和preprocessing](../campaign/models.py)。输入只包含实验前特征，后来的访问、购买、消费结果都不放进去。否则相当于考试时把答案夹进题目。

## 用训练集练习 用验证集选方案 用测试集交卷

**目标：避免在同一批数据里挑出漂亮答案，又拿这批数据证明自己优秀。**

项目将64,000人划为三份：

| 数据 | 人数 | 用来干什么 |
|---|---:|---|
| 训练集 | 38,400 | 学习回归系数、树的分支等 |
| 验证集 | 12,800 | 选择模型、触达比例、统一内容 |
| 测试集 | 12,800 | 给选好的规则做最终评估 |

可以把它理解成练习题、模拟考和期末考。模拟考可以帮助选择学习方法，期末考成绩出来后不能修改答案，再声称刚才那份成绩是独立检验。

划分按随机处理组保持大致比例，种子固定为2026；没有为了让购买人数好看而按购买结果重切。三个用户集合不重叠。

后面提到的“五折交叉拟合”发生在训练集内部，不会用掉这份独立测试集。

## 逻辑回归预测谁本来就会购买

**目标：建立一条简单基线，看增量模型是否真的比挑高购买概率用户更有用。**

逻辑回归把用户特征乘上学到的权重，相加得到一个分数，再把分数转换成0到1之间的概率。比如0.02，意思是类似特征的用户中，预计约2%会购买；不是这个人必然会买，也不是预计消费0.02美元。

训练时，真实标签只有0和1。模型会惩罚错误且过于自信的预测，逐步调整权重。

本项目只用**不发邮件组**的训练用户来学这个模型。因此它回答的是：“没有这次邮件时，这类人有多大概率购买？”之后选出概率最高的同样数量用户，给他们发送验证集选定的统一邮件。

实际使用`LogisticRegression(C=0.5, max_iter=1000)`。`C`控制正则化强度，值越小约束越强；`max_iter`是优化迭代次数上限。

为什么只靠它可能不够？看这个教学例子。下表写的是购买概率，与下一节的消费金额例子分开：

| 用户 | 不发邮件的购买概率 | 发邮件的购买概率 | 增加多少 |
|---|---:|---:|---:|
| 甲 | 80% | 81% | 1个百分点 |
| 乙 | 10% | 30% | 20个百分点 |

按自然购买概率会先选甲，按购买概率增量会先选乙。甲即使不收到邮件也很可能买，邮件改变他的空间很小。

项目中的增量模型进一步以**消费金额增量**为目标，因为额外买一次多少钱也会影响经营价值。购买概率基线是常见简单做法，不是对同一金额目标的等价建模。

代码里的`conversion`模型就是这个逻辑回归。它没有预测谁会被分到实验组；随机分组概率本来就已知。

## T-Learner分别估计三种情况下会消费多少

**目标：估计发某种邮件，相比不发，会额外带来多少消费。**

教学例子：

| 用户 | 不发邮件的预期消费 | 男装邮件 | 女装邮件 |
|---|---:|---:|---:|
| 甲 | 100美元 | 101美元 | 100.5美元 |
| 乙 | 1美元 | 4美元 | 2美元 |

甲的男装增量是1美元，乙是3美元。如果成本一样且只有一次触达机会，按这些预测应该选乙。

难点是：一个人实际只能经历一种情况。给甲发了邮件，就看不到同一时间完全不发邮件的甲。那个没发生的结果叫**反事实**。

T-Learner的办法是分别训练三个模型：

```text
不发组的数据 → 模型0 → 预测不发时的消费
男装组的数据 → 模型1 → 预测男装时的消费
女装组的数据 → 模型2 → 预测女装时的消费
```

对一个新用户，把同一套特征送进三个模型，再相减：

```text
男装增量 = 模型1的预测 − 模型0的预测
女装增量 = 模型2的预测 − 模型0的预测
```

T-Learner是一种组织模型的方式，不限定里面必须用哪种算法。本项目分别装入Ridge和随机森林，得到两套候选方案。名字虽叫T-Learner，这个三臂实验实现有三个结果模型。

“类似用户预计多消费多少”的正式名称是**条件平均处理效应CATE**。它是带不确定性的平均效果预测，不是发现了某个人真实、可直接验证的两个平行人生。

原始随机分配让不同组具有可比性。单纯把日常“发过邮件的人”和“没发过的人”分开训练，如果发邮件本来就按购买意愿挑人，差值可能混入原有人群差异，不能自动得到因果效果。

代码对应：[revenue_models和rankers](../campaign/models.py)。

## Ridge回归给线性预测加一道约束

**目标：提供一个通过限制系数、降低过拟合风险的线性消费预测基线。**

如果你学过计量回归，可以先想普通线性回归：

```text
预计消费 = 基础值 + 历史消费特征×系数 + 购买间隔×系数 + 渠道等项
```

这些系数从数据里学。普通最小二乘努力缩小预测误差；Ridge同时要求系数不要太大。它愿意牺牲一点训练集拟合，换取更稳定的预测。

可以把系数想成音量旋钮。有些特征在这一批样本里碰巧很有用，普通拟合可能把旋钮拧得很大。Ridge对大幅度旋钮加罚，减少把偶然现象放大的机会。它仍然使用平方误差，对极端消费记录敏感，不是专门抵抗异常值的方法。

它也不是把所有预测都压低。教学例子：某个标准化特征取−1、1，对应消费10、30，普通回归可以给出“20加10倍特征”。加入惩罚后，若系数变成5，预测就变成15、25：低的上调，高的下调。这是在约束特征对预测的影响。

实际设置是`Ridge(alpha=100)`。100是惩罚强度，不是把预测乘100，也不表示100棵树。各特征先标准化，是为了让系数约束有可比的尺度。

它能解决一定的方差和共线性问题，但基本形式仍然简单。例如“近期买过且来自网页渠道”才特别响应，单纯加和可能表达不好，所以项目还比较随机森林。

Ridge的原始预测可能小于零。这是线性预测的局限，不代表真实消费允许负数；代码没有把所有负预测机械截断，因为截断也会改变均值和差值。

项目每个实验臂一个Ridge，共3个。方法定义可对照[scikit-learn的Ridge说明](https://scikit-learn.org/1.6/modules/generated/sklearn.linear_model.Ridge.html)，实际参数以[models.py](../campaign/models.py)为准。

## 随机森林让很多棵树一起判断

**目标：学习更复杂的分情况关系，例如购买间隔与渠道共同影响消费。**

先理解一棵回归树。它按特征把人分到不同分支，最后用叶节点中训练样本的平均消费做预测。

教学示意，分支并非从本项目某棵树摘录：

```text
最近3个月买过吗
├─ 买过 → 历史消费较高吗
│         ├─ 较高 → 这一叶子平均消费8美元
│         └─ 较低 → 这一叶子平均消费2美元
└─ 没买过 → 再按其他特征划分
```

训练时，算法寻找让子组内部结果更接近的切分。连续切分就能表达交互：同样是高历史消费，近期买过和很久没买的人可以走向不同叶子。

一棵树容易受偶然样本影响。随机森林通过有放回抽样形成不同训练样本，训练多棵树，把预测平均。它们仍然可能有共同偏差，因此“很多棵”不等于一定正确。

T-Learner里的实际设置是：

| 参数 | 值 | 白话含义 |
|---|---:|---|
| n_estimators | 100 | 每个实验臂训练100棵树 |
| max_depth | 5 | 限制树最多往下分多少层 |
| min_samples_leaf | 250 | 一个叶子至少需要足够多的训练样本支撑 |

限制深度、增大叶子，是因为消费很稀疏：不能让两三个大买家单独决定一个看似精准的人群规则。随机森林有许多版本，这份代码没有设置每次切分只看平方根数量特征；使用的默认`max_features=1.0`允许考察全部输入特征。

这里的Random Forest是机器学习算法；零售分析里的RF分群是Recency/Frequency，两个缩写容易撞名，但做的事情不同。

## DR-Learner先修正预测 再学习增量

**目标：利用随机实验里已经观测到的结果，修正单靠消费预测相减的误差。**

T-Learner先预测三种消费再相减。DR-Learner增加一步：给预测加上“按随机分配概率放大的预测误差修正”，构造一个用于学习的增量分数。

先看教学例子，只看男装邮件这一种处理：

```text
模型预测这个人收到男装邮件会消费10美元
他实际收到男装邮件，消费了16美元
预测少了6美元
每个人分到男装组的机会是1/3
修正分数 = 10 + 6 ÷ (1/3) = 28
```

**28是统计计算中的分数，不是这个人实际花了28美元，也不是已经知道他的真实增量。**

为什么误差乘3？因为只有约三分之一的人真正收到男装邮件，我们只在这些人身上看到该处理下的真实结果。逆概率加权让这部分观察到的误差，在平均意义上代表相应的随机抽样份额。

一个更容易核对的思想例子：假设100名类似用户，模型都预测10美元，而每人收到男装时都消费16美元。每个人有三分之一概率被随机分到男装组。他若进男装组，分数28；否则分数10。分数的期望是：

```text
1/3 × 28 + 2/3 × 10 = 16
```

所以平均修正有机会把有偏的10拉回目标16。实际数据远比这个例子嘈杂，个别分数可以很大或为负，不能逐个人拿它当事实。

本项目对不发、男装、女装都构造这种分数，再做差：

```text
男装增量伪标签 = 男装修正分数 − 不发修正分数
女装增量伪标签 = 女装修正分数 − 不发修正分数
```

“伪标签”就是按照统计方法构造的学习目标。它不是原始数据里直接提供的“这个人被营销影响了多少”。

最后训练两个随机森林，分别从用户特征预测这两个增量伪标签。这里每片森林100棵树，最大深度4，最小叶节点300，比前面的结果森林更保守。

为什么叫“双重稳健”？一般而言，结果预测模型和处理概率模型中有一方正确，就能支持相应估计的稳健性质。本项目直接使用随机设计给定的`1/3`，没有训练处理概率模型。有限样本噪声、特征不足、用户之间相互影响等问题仍然存在，所以这个名字不代表不会失败。

本项目的计算见[fit_all](../campaign/models.py)与[dr_scores](../campaign/stats.py)。想看正式定义时，再读[DR-Learner方法论文](https://arxiv.org/abs/2004.14497)；第一次阅读不需要先掌握证明。

## 五折交叉拟合让修正误差更可信

**目标：一个人的修正分数，不能依赖已经看过他答案的模型。**

假如模型在训练时记住了某人的实际消费，预测误差会异常小。再拿这个小误差来修正和构造伪标签，会高估模型的可靠性。

项目把训练集分成A、B、C、D、E五份：

```text
用BCDE训练 → 预测A
用ACDE训练 → 预测B
用ABDE训练 → 预测C
用ABCE训练 → 预测D
用ABCD训练 → 预测E
```

所有训练用户都能得到预测，但预测他的模型没有用过他的消费答案。这叫交叉拟合，产生的预测叫OOF预测，即来自该用户所在折之外的模型。

每轮的编码器和标准化也只在四份训练数据上学习。之后用这些预测构造增量伪标签，再训练第二阶段森林。外面的验证集、测试集依然保留各自用途。

代码中第一阶段用Ridge；不是先用测试数据训练森林，再计算测试增量。

## 模型分数怎样变成一份触达名单

**目标：把“预计多消费多少”变成“联系哪些人、发什么”。**

教学例子：预计触达甲多消费1美元，乙多消费3美元。假设每1美元额外消费能留下0.3美元收益，一次联系花0.05美元：

```text
甲：1 × 0.3 − 0.05 = 0.25美元
乙：3 × 0.3 − 0.05 = 0.85美元
```

只够联系一个人时，选乙。若某人所有内容的预计净增量都不大于零，则不联系。

代码对每个人先比较男装与女装，取预计净收益较高者；再对人排序，在人数上限内选人。`0.3`和`0.05`都是经济情景假设，不是原数据提供的真实毛利或成本。

验证集比较三套增量模型，以及15.625%、30%、50%、100%四种触达上限；还保留“不联系任何人”候选。15.625%来自“64,000人最多联系10,000人”的容量假设。

**项目结果：**在15.625%上限下，验证集选中DR-Learner；测试集12,800人中触达2,000人，其中1,081人男装、919人女装。统一内容基线由验证集选为男装邮件。

这里约束的是人数。如果不同用户的券额和核销成本不同，就不能把“同样联系2,000人”当成“同样花了多少钱”；迁移到真实补贴需要重新设置成本约束。

实现见[targeting](../campaign/stats.py)和[验证选择记录](../reports/campaign/validation_selection.csv)。

## DR策略评估给整套规则算成绩

**目标：判断新规则在独立数据上是否比简单做法更好。**

这一步最容易和DR-Learner混淆。两者复用了类似的修正公式，但工作不同：

| 环节 | 做什么 | 使用哪份数据 |
|---|---|---|
| DR-Learner训练 | 学习不同用户的增量，形成评分规则 | 训练集 |
| 选择策略 | 选择模型、容量和统一内容 | 验证集 |
| DR策略评估 | 为已经选好的规则估计价值和误差范围 | 测试集 |

测试数据里，每个人实际收到的邮件是随机决定的，新规则可能建议另一种处理。这就像手里只有随机试营业的记录，却想估计“按这套新名单经营”平均会怎样。这个任务叫离线策略评估，英文缩写OPE。

项目使用训练集拟合的Ridge预测测试用户的三种消费，然后结合实际随机处理和消费，得到上一节那种修正分数。

假设某人三种分数分别是`[不发2，男装6，女装4]`，只是教学例子：

```text
策略建议男装：对这人的增量评分 = 6 − 2 = 4
策略建议女装：增量评分 = 4 − 2 = 2
策略建议不发：增量评分 = 2 − 2 = 0
```

对所有合格用户取平均，就是这套规则相对全部不发的估计增量。**分母包含没有被触达的人**，不是只在名单里的2,000人中取平均。

“随机联系同样比例的人，统一发男装”也能评分。若随机触达比例25%，上例该人的期望增量评分是`25%×4=1`。不需要反复抽随机名单，挑一个差结果来衬托模型。

此外还计算HT估计作为检查：它省掉结果预测，只按随机分配概率对观测结果加权。DR与HT都利用同一随机实验，并不是两份独立证据。

## 为什么要逐人相减再算不确定性

**目标：公平比较同一批人上的两套规则，并估计差异有多不稳定。**

教学例子，两套策略在三个用户上的评分为：

| 用户 | 策略甲评分 | 策略乙评分 | 甲减乙 |
|---|---:|---:|---:|
| 1 | 4 | 3 | 1 |
| 2 | 0 | 1 | −1 |
| 3 | 6 | 4 | 2 |

逐人差值平均是`(1−1+2)/3≈0.667`。不确定性也应从这一列差值计算，因为同一人的两种评分相关。不能把两个置信区间的端点直接相减。

代码用差值的样本标准差除以人数平方根，得到标准误，再构造t区间。这个区间描述当前冻结规则的抽样不确定性，没有包含未来重新训练、重新选模型的全部波动。

**项目结果，单位为美元/合格用户：**

| 策略 | 触达比例 | 相对全部不发的增量消费点估计 |
|---|---:|---:|
| 等量随机发男装 | 15.625% | 0.0982 |
| 自然购买概率定向 | 15.625% | 0.2378 |
| DR定向 | 15.625% | 0.0922 |

DR定向减等量随机的配对差是约`−0.006`，95%置信区间为`[−0.279，0.267]`。现有证据同时容许损失和有意义的收益，不能确认定向更好，也不能证明两者等效。

95%置信区间可以理解为：在假设与近似成立时，在同样条件下反复抽样、按同样办法构造区间，约95%的区间能覆盖对应的真实效果。当前消费稀疏且有大额记录，t区间没有严格的有限样本覆盖保证，也不是对未来结果的保证。

购买概率策略点估计较高，但其与定向策略的差异也有较大不确定性，不能只凭表中大小宣布胜负。

原始聚合结果：[策略表](../reports/campaign/policies.csv)、[配对比较](../reports/campaign/paired_comparisons.csv)。

## 平均营销有效 为什么定向仍然不一定更好

**目标：把“要不要营销”和“要不要为个性化多投入”分开回答。**

假设一个班每个人补课都能平均多考5分。你已经证明补课有效，但还没证明自己能准确挑出“补课最能多考分”的学生。随机选人补课也可能获得同样平均收益。

项目的全量实验显示：不发邮件购买率0.5726%，男装1.2531%，女装0.8837%。对应平均提升约0.6805和0.3111个百分点。这个问题使用的是全量64,000人。

个性化评价要回答“相同触达人数下，多赚多少”，使用冻结的12,800人测试集。它需要学习哪些特征能区分营销效果，比判断平均效果更难。

这份数据的困难尤其明显：64,000人只有578名买家，约99.10%的消费为零；测试集只有124名买家。少量大额消费就能改变结果，而模型只能看到有限的历史特征。

因此项目用了正则化、浅树、大叶子、交叉拟合和独立测试。它们能减少一些错误，但不能凭空增加购买记录。按预测增量分组检查时，最高预测组也没有稳定表现出最高实际增量，说明排序能力尚未得到充分验证。

这里保留负结果，是为了回答真实决策问题。换更复杂模型、换随机种子，直到测试结果好看，会破坏这份评估的意义。

## 实验检查是在确认比较的基础

**目标：先排除明显数据和分组问题，再计算平均效果。**

SRM检查三组人数是否明显偏离设计的1比1比1。它类似检查随机发三种颜色卡片时，有没有某种颜色异常少。项目的p值约0.904，未发现这种人数异常。

SMD检查实验前特征差异，例如男装组是否一开始就都是高消费客户。最大绝对SMD约0.0137，检查到的差异较小。这两项通过，只代表没发现对应异常，不能证明任何偏差都不存在。

ITT要求所有原始分配用户进入比较。有人没有打开邮件，也要留在原组，因为业务真正能控制的是分配触达，不能事后只挑配合的人。

如果只比较访问过网站的人，邮件可能已经改变谁会访问，留下来的两群人就不再具有原来的随机可比性。因此原始分配组购买率，比“访问者中的购买率”更适合回答邮件总体效果。

Holm校正处理同时做多个检验带来的误报机会。本项目主要比较男装对不发、女装对不发，两次购买率检验作为一组校正；不能把逐指标校正说成所有探索都统一控制。

另外，“某类用户效果显著，另一类不显著”不等于两类效果显著不同。要判断差异本身，仍然需要直接比较两类效果。

实现见[audit、balance和itt](../campaign/stats.py)，结果见[实验报告](../reports/campaign/REPORT.md)。

## CUPED式调整尝试去掉能预先解释的波动

**目标：在平均效果估计里，减少用户原有差异带来的噪声。**

还是补课例子。学生原来的成绩差异很大，如果原成绩能预测新成绩，比较补课时可以利用原成绩，减少“本来基础就不同”的自然波动。

电商里对应的是历史消费。本项目先在训练集学习“历史消费通常能解释多少后续消费差异”，再把这套调整应用到测试集。它没有直接拿实验后消费减历史消费，因为两个窗口不同、单位关系也未必是一比一。

实现采用`log(1+过去一年消费)`，估计斜率时在各随机组内去均值，避免把组间平均处理差异混入斜率。参数只用训练数据估计，然后计算调整后的组间差异。

**项目结果：**收入效果估计的方差仅下降约0.026%和0.004%，改善很小。这表示当前协变量和调整方式没有带来明显精度收益；不能写成显著降方差。

CUPED式调整在这里服务于实验估计，没有给用户选择邮件，也没有替代DR-Learner。代码见[adjusted_effects](../campaign/run.py)。

## 拆开选人和选内容 但保留不确定性

**目标：进一步理解定向策略的差异可能发生在哪一步。**

原策略同时“选人”和“选内容”。项目增加一个诊断参照：沿用完全相同的定向人群，但所有人都发统一男装邮件。

这样可以顺着两个步骤比较：

```text
随机人群发男装
→ 定向人群发男装：看人群选择项
→ 相同定向人群按模型选内容：看给定人群后的内容选择项
```

项目点估计分别为`+0.093`和`−0.099`美元/合格用户，相加正好约`−0.006`。不过两项的区间都很宽，不能据此断言内容选择已经被证明是失败原因。

这是沿指定比较顺序的价值拆解，不是唯一的因果机制解释。该分析又使用了已经看过的测试集，所以属于回顾诊断；没有重新选一套表现最好的人群再包装成独立验证。

对应[人群与内容分解](../reports/campaign_decision/audience_content_decomposition.csv)。

## 最终要看是否覆盖成本 以及还要多少数据

**目标：把效果估计变成有门槛的投入决定。**

教学例子：复杂模型多带来0.02美元消费/人，覆盖100万人，假设每1美元额外消费留下0.3美元收益，则额外收益是6,000美元。如果额外开发维护成本10,000美元，这个效果仍不够。

因此同触达成本下，最低值得投入的消费优势是：

```text
额外实施成本 ÷ 覆盖人数 ÷ 收益折算比例
```

实际成本未知，就应给成本情景和决策条件，不能编出一个确定ROI。区间全部高于门槛才支持达到要求；全部低于门槛表示不足以达到要求；跨过门槛表示证据仍不足。

样本量是在问：“如果确实存在我关心的优势，需要多少人才能较有把握发现？”结果越嘈杂、想识别的优势越小，需要的人越多。

项目中两个数字容易混淆：

| 设计情景 | 样本需求 | 数字含义 |
|---|---:|---|
| 购买率三臂实验，识别0.3个百分点提升 | 每组约15,152人 | 每组人数，80%功效，保守分配两次主要比较的检验预算 |
| 冻结策略的未来三臂随机日志评估，识别0.05美元/人优势 | 总计约781,462人 | 新的独立评估总人数，使用pilot配对分数方差 |

第二个数字假定仍按三臂随机采集并使用同样DR评估，不能直接套到“两套策略直接A/B”的每组人数。它也不是已经跑过78万人，而是后续设计情景。

迁移到补贴时，还要明确平台收入、实际核销成本、退款追回和长期购买。成交额不等于平台收入，同发券人数也不等于同实际成本。具体方案见[补贴实验迁移设计](EXPERIMENT_DESIGN.md)。

## 回到经营分析 RF分群先描述客户

**目标：形成易解释的客户状态，帮助提出调查和运营假设。**

教学例子：甲昨天买过、历史买过20次；乙昨天第一次买；丙200天没买。三个人值得关注的事情显然不同。

零售RF指最近购买Recency和购买频次Frequency。项目把截至2011年8月底的R和F分别分成五档，再按固定规则划为沉默、忠诚、近期低频、常规四类。历史金额M用来描述画像，没有参与标签规则。

随后看9—11月未来表现。**项目结果：**忠诚组未来购买率约77%，沉默组约21%。这表示标签有行为区分度，仍然不告诉我们谁收到优惠后增加最多。忠诚组可能本来就会买。

提前定标签，再看后续结果，是为了避免用后来的购买倒推标签，制造“忠诚用户果然买得多”的循环论证。

代码位于[零售SQL](../sql/retail_marts.sql)的时间外RF分群部分。

## 复购分析先保证每个人有足够观察时间

**目标：判断用户会不会再次购买，同时避免把没观察到误当成没发生。**

教学例子：甲已经观察90天，乙只观察8天。甲90天没回来买和乙8天没回来买，不能都记成“90天未复购”。

项目只让观察期已经成熟的人进入相应分母；另固定3,530名具有完整90天观察窗口的用户，比较30、60、90天累计复购，分别约16.4%、29.8%、38.8%。

同一天的两张发票可能是一次采购拆单，所以要求更晚日历日的购买才计为复购。数据开始时第一次看到某人，也不表示他真实第一次购买；设置预热期只能减轻这个问题。

“首次观察”“回流购买”都是这份数据中的行为定义，不能直接写成新增注册或营销召回成果。实现见[cohort和repurchase相关SQL](../sql/retail_marts.sql)。

## Shapley分解把同时变化的因素分清楚

**目标：把购买金额的变化按一套不依赖任意替换顺序的规则分账。**

先看教学例子：原来一单10件，每件2元，共20元；现在12件，每件3元，共36元。多出来16元，件数和单位金额各算多少？

先改件数：20变24，再改单位金额：24变36。分到4和12。

先改单位金额：20变30，再改件数：30变36。分到10和6。

Shapley把顺序平均：件数分到`(4+6)/2=5`，单位金额分到`(12+10)/2=11`，合计仍为16。

项目进一步把金额写成“买家数×人均订单×每单件数×成交单位金额”，枚举四个因素全部24种替换顺序后取平均。每项贡献加起来必须等于总变化，这是重要对账检查。

回到两因素的单均金额分解，**项目结果是：**可识别客户单均金额下降约£19.62，其中每单件数项−£5.93、成交单位金额项−£13.69。它与四因素分解的总购买金额不同，单位是每单英镑。

这项分析没有训练预测模型，也没有做“人为让客户多买两件”的实验。分到某项的金额不能直接解释成某个运营动作肯定能追回的收益。

实现见[product_shapley](../retail/diagnose.py)和[四因素分解](../retail/customer_drilldown.py)。

## 商品组合分解判断平均买得便宜是怎么回事

**目标：避免看到整体平均单位金额下降，就认定所有商品都降价。**

教学例子，店里只有10元和1元两种商品，价格一直没变：

| 时期 | 10元商品件数占比 | 1元商品件数占比 | 平均单位金额 |
|---|---:|---:|---:|
| 原来 | 50% | 50% | 5.5元 |
| 后来 | 20% | 80% | 2.8元 |

平均少了2.7元，完全来自便宜商品的购买件数占比提高；没有给总件数时，不能据此判断其绝对销量增加了多少。

项目分别检查共同SKU内部单位金额变化、共同SKU销量占比变化，以及只在某一期成交的SKU和覆盖率变化。只在当前期成交不代表新品，只在基期成交也不代表下架。

**项目结果，单位为英镑/件：**共同SKU内部变化约−0.00785，组合变化约−0.08380，覆盖与进入退出合计约+0.03734，总计−0.05430。组合变化对应更大的向下分量，因此不能把总体下降简单解释成普遍降价。

再往下查，发现小剪刀83.19%件数集中一张发票，而圣诞装饰低价档覆盖172/174名客户。这分别指向批量订单条件和广泛价档变化的调查，不能统一归为“大客户买多了”。

即便同一个商品价格下降、销量增加，也可能同时发生圣诞旺季、曝光增加或补货恢复。要判断降价造成多少销量，需要更强设计和数据；分解本身不能识别价格弹性。

具体证据见[经营诊断](../reports/retail_diagnosis/DECISION_MEMO.md)与[SKU下钻](../reports/sku_drilldown/FINDINGS.md)。

## 为什么先核对统计范围 再解释经营原因

**目标：保证我们没有在解决一个由口径制造的假问题。**

项目最初的问题是：2011年11月相较2010年11月，可识别买家多3.36%，购买金额却少1.68%。但把匿名交易和退货账簿核对后，全体商品净额实际增长2.34%。

缺少客户ID的交易仍然有金额，不能因为算不出是哪位客户就全删掉。于是结论被收窄为“可识别客户部分下降”，没有直接推出全店需求下降。

再用2010年1—10月历史金额冻结38名高购买额客户，发现他们两个11月之间少了£38,225，其他已识别客户多了£18,781。名单早于两个待比较的11月，避免看见谁下降才选谁；它仍然是一项回顾研究。

如果怀疑他们提前采购，还必须逐个客户核对。甲11月少100、甲前两月多30，最多只能说30在金额上相容；乙多买100不能拿来解释甲。38人名单中，21名11月减额客户合计减少约£97,975；这些客户前两个月的正增额逐人封顶，只能覆盖约£20,638，即21.06%。这个分母是减额客户的合计减额，不是整份名单增减相抵后的£38,225。整个名单跨月合计转正，仍不足以关闭这些客户的调查。

这些分析给出查谁、查什么、哪些解释还没排除。它们没有证明给这38人发券一定有效，更没有与另一份邮件实验连接起来。

## SQL和Hive负责把账算可靠

**目标：让模型和业务判断使用口径清楚、可复现的数据。**

一张发票可能有十行商品，不能当十笔订单。项目先清理商品行，再聚合到订单、用户月、指标表，避免人数与金额被重复计算。

百万行零售数据用openpyxl逐行读取，每50,000行写入DuckDB，再用SQL聚合。分批处理没有抽掉其余数据；256MB是DuckDB配置的内存预算，不是整个程序的峰值内存保证。

实际Hive执行的是完整64,000行实验数据：

| 层次 | 类比 | 本项目工作 |
|---|---|---|
| ODS | 收货区 | 接入原始CSV |
| DWD | 整理后的货架 | 转类型、按处理组分区、保存ORC明细 |
| ADS | 给业务看的账表 | 聚合实验人数、购买、消费等指标 |

Hive运行中遇到客户端Java/JLine初始化及SQL脚本未真正执行的问题，通过运行参数、终端配置和提交方式调整解决；最终根据查询结果、表格式、分区和日志确认执行。容器启动或退出码为零都不足以证明算对了。

另用Python独立聚合，与Hive核对三组各7个指标，共21项。当前34项测试还覆盖匿名交易、拆单、观察窗口、分解恒等式、配对策略和预算等容易影响结论的逻辑。

完整零售分析在DuckDB完成，Hive验证在64,000行实验数据完成，均为独立项目环境。运行说明见[Hive工程说明](../infra/README.md)与[验证记录](VALIDATION.md)。

## 用几道小题检查自己是否理解

先尝试自己回答，再看下面的答案。

1. 甲不联系预计消费100，联系后101；乙不联系1，联系后4。在相同成本下只联系一个人，按这组预测选谁？
2. Ridge与T-Learner是同一层面的两个模型吗？
3. DR算出一个人的男装分数28，可以说他收到邮件会花28美元吗？
4. DR-Learner已经学会选人，为什么还要DR策略评估？
5. 实验显示邮件平均有效，是否证明定向优于随机？
6. 95%区间跨过零，是否证明真实效果是零？
7. 10元商品卖少、1元商品卖多，整体均价下降，是否证明降价？
8. 零售RF标签的忠诚组复购率高，是否证明应该优先补贴？

答案：1选乙，预测增量3大于1。2不是，Ridge是回归器，T-Learner是组织多个回归器估计增量的方法。3不能，28是经过概率加权的统计分数。4前者负责学习，后者在独立数据上检验整套规则。5不证明，还要同容量比较。6不证明，可能证据不够精确。7不证明，商品组合就能改变均价。8不证明，本来就买的人未必有较大补贴增量。
