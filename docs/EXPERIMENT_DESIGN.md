# 从公开研究到用户补贴实验：待实施方案

这份方案是项目的业务迁移产物；没有在抖音投放、发券或上线。Hillstrom 是内容触达 RCT，其效果与样本量不能直接迁移到券额实验。

## 决策与准入

先回答“哪个经营问题需要补贴、谁可能受益、在什么窗口回收成本”。本项目的高购买额客户和海外订单篮子诊断只决定调查优先级；没有库存、运费和优惠日志时，不能直接把这些分组变成发券人群。若只是采购月份移动，优先跟踪采购节奏；若存在商品供给约束，先修复供给；只有成本或购买门槛的机制证据成立，才进入对应激励实验。

准入人群由分组前购买频次、距上次购买时间和合法可用的消费特征定义；排除互斥活动、风控拒绝和不满足券使用条件的用户。不可用是否领券、是否核销或实验后加购来决定处理组。新客与存量用户单列实验，避免把激活与拉新混为一项收益。

若要比较普通运营与定向策略，实验单位为用户，稳定哈希随机分配：不补贴、随机补贴策略、冻结评分定向补贴策略。策略臂内部的所有准入用户均进入ITT分母，不能只比较最终被策略选中或核销的人。各组符合条件人数与随机概率写入 assignment 表。券面额与门槛来自运营预算和可确认的单位经济性；没有这些数据时，方案保留参数，不凭邮件实验虚构最优券额。内容、入口、频控与券条件保持可比。商家库存或直播间存在明显溢出时，评估商家/直播间聚类随机化及设计效应，不能继续套独立用户标准误。

**相同发券比例不等于相同实际补贴成本。** 定向可能改变核销率、券额结构和退款追回。若约束是预算，在实验前用独立历史数据规划预期成本相近的固定策略，并预先规定预算护栏；最终报告实际成本差与净贡献差。不能看完结果后删掉高成本用户以配平预算，也不能把Hillstrom的同触达比较称为已完成同核销成本比较。

## 指标与成本合同

|指标|分子与分母/窗口|用于什么决策|
|---|---|---|
|D14 支付购买率|分配后14天有有效支付的用户/全部分配用户|主要用户效果，ITT|
|D30 平台净贡献/分配用户|成熟订单可确认的平台佣金/服务收入，减未已冲减收入的平台券净结算支出及其他边际成本，按用户归集|经济主指标；与转化主指标采用事先确定的检验顺序|
|增量成本|处理组单位用户核销及触达成本减对照对应成本|增量 ROI 分母；零或负值时不报告普通比率|
|D30 复购、退款、投诉|固定用户窗口、成熟订单窗口、全部分配用户投诉率|护栏；阈值在看结果前确定|
|核销率|已核销券/发放券|解释路径和预算，不能代替 ITT|

增量净贡献直接做用户级差值与区间。增量 ROI 定义为“增量净贡献/增量成本”，成本前贡献回报定义为“增量成本前贡献/增量成本”；二者分别命名。不能使用活动组总 GMV/补贴总额充当因果 ROI。成本差接近零或区间覆盖零时，不用不稳定的比率作为主要决策指标，优先报告净贡献差、成本差及各自不确定性。对账明确平台券/商家券承担方、叠券分摊、取消单、退款后追回与活动归属；跨场景用户仍保持一个稳定实验分组。

## 平台与商家经济口径必须分开

本项目的交易金额是零售账簿金额，不是电商平台收入。迁移到平台时，应先由财务确认以下计量合同；这不是对抖音实际结算规则的断言。

|层次|如何归集|必须避免的错误|
|---|---|---|
|交易规模|固定支付/退款窗口及优惠前后定义，分别记录买家实付、商品成交额与平台/商家承担优惠|把GMV当成平台营业收入；混用优惠前与优惠后金额|
|成本前平台贡献|按结算规则记录成熟订单的可确认佣金/服务收入，扣除与策略无关、已规定的变动成本|把商家商品毛利率直接当平台贡献率|
|平台券净成本|平台实际承担支出减退款追回与其他已核实返还；检查是否已冲减收入|既从净收入中体现优惠，又再扣一次同笔优惠|
|商家承担优惠|单列用于机制、结算和商家护栏，只有平台实际承担部分进入平台券成本|把券面值、平台成本、商家成本视为同一金额|
|最终单位净贡献|用户所有合格场景的成本前贡献减平台券、触达及新增边际服务成本|只统计券订单或被触达场景，遗漏自然订单和跨场景替代|

一个可审计的规则是：每个结算事件有唯一`settlement_event_id`、承担方、币种、金额、发生时间和关联订单/券，并以借贷或方向字段明确流入流出。用户净贡献按同一实验窗口归集；迟到退款成熟后重算。退款窗口、可确认收入口径和费用项由实际业务合同确定。

## 要防止“短期拉动”被当作新增需求

若补贴使用户提前购买，D14转化可以上升而D60累计净贡献没有改善。因此同时预先定义D14作用窗口和D30/D60累计净贡献、购买频次及护栏；长期窗口采用事先固定的检验层级，不逐个挑显著结果。需要足够随访且记录退款成熟，不能用未成熟窗口判输赢。对原本会自然购买的高价值用户，补贴可能只降低贡献；这正是保留不补贴组和全体准入用户ITT分母的原因。

D30/D60分别纳入分配后`[0,30)`/`[0,60)`天内支付的订单，在事先固定的额外退款成熟期结束后确认净结算。不能只筛选报告日已成熟的订单，否则不同处理组的退款和确认速度可能改变纳入范围；全部分配用户始终保留在ITT分母。订单、退款与成本用同一预定关账规则。

跨短视频、直播、商城的用户保持一致分组，在用户总结果之外再做场景辅助归因。单场景增长若被其他场景下降抵消，不能称平台总增量；没有可靠场景日志时不输出场景ROI。

## 分组、样本量与停止

用同类目标人群最近可用窗口的控制购买率及用户净贡献方差规划样本量。购买率选定最小有业务意义的绝对 MDE；多处理组用 Dunnett 或保守 Bonferroni 规划，分析与检验规则预先固定。净贡献重尾时以用户历史样本重抽验证功效，不仅计算购买率功效。聚类设计增加设计效应。公开邮件控制购买率0.573%只用于本仓库教学计算，不充当抖音基线。

主要策略对比为“定向策略减随机策略”。Dunnett仅覆盖多个策略与共同不补贴组的比较，不自动覆盖这个策略间对比；策略间对比及跨窗口检验按预先确定的检验族、层级或Holm/Bonferroni规则控制错误率，功效规划与实际主要对比保持一致。

先检查分组/曝光一致性、样本比例失配（SRM）、重复分组、日志缺失和成本对账，再读效果。以全部分配用户分析；实际曝光或核销分析只作为辅助。固定观察窗口和退款成熟时间，禁止每天看到 p<.05 就结束；需要连续监测时预先指定序贯检验或 alpha spending。异常成本、投诉或风控触发可以安全停止，但这种停止下的推断需要重新解释。

## 交付给产品、算法与研发

产品拿到人群准入、运营动作、触达上限、券条件、经济阈值和护栏；算法拿到仅分组前可用的特征快照、冻结模型版本及评分阈值；研发拿到用户稳定分组、互斥关系、幂等发券、归因和对账合同。

最小事件字段：`user_id, experiment_id, arm, assignment_probability, assigned_at, feature_snapshot_at, policy_version`；触达另记 `contact_id, scene_id, contacted_at`；券另记 `coupon_id, face_value, threshold, platform_share, issued_at, redeemed_at`；订单另记 `order_id, user_id, paid_at, paid_amount, refunded_amount, settled_cost`。订单和券通过明确关联键对账，不能通过后验相似特征强行关联。每张表声明粒度、唯一键、时区、迟到数据与补数规则。

本项目的落地建议是：公开实验支持内容激活存在平均效果；稀疏收入下，现有定向模型优势尚未成立。因此上线前应先补齐成本合同、预注册独立验证，保留简单策略基线与不触达选项，再决定是否引入复杂模型。
