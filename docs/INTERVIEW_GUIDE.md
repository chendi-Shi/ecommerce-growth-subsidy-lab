# 面试讲解与复现要点

开场可说：我将“交易增长来自哪里”和“触达是否带来额外收入”拆成两个可识别问题。前者用真实交易建立买家与复购指标，后者用真实三臂随机实验验证增量策略；两者来自不同商家，不拼接成一个实验。这里的难点是口径、识别和策略评估，不是把算法名堆到简历里。

## 十个追问与可辩护回答

1. **为什么没有直接预测谁会购买？** 高购买概率可能是自然需求。T-Learner 分别估计各臂收入均值，差值是 CATE；DR-Learner 用训练集交叉拟合的残差构造效果目标。因果评分回答谁受触达影响，仍需留出实验数据验证策略价值。
2. **实验开始前要定什么？** 本次再分析的主要假设是邮件提升每分配用户两周购买率；主指标 conversion，两次邮件对照比较属于同一检验族。访问和收入为辅助指标，收入另用于经济策略目标。明确总体、分配单位、窗口、MDE、停止规则、护栏和多重检验后再开实验。本项目为历史数据再分析，分析计划不能伪称原始实验预注册。
3. **为什么是 ITT？** 以分配臂比较所有客户；是否访问、打开或购买是处理后行为。只比较访问者会引入选择偏差，访问条件转化只能描述漏斗，不能替代总体因果效果。
4. **SRM 与平衡检验有什么区别？** SRM 检查三臂人数是否偏离设计比例；SMD 检查处理前特征差异。二者用于排查分流/数据问题，不证明没有所有偏差，也不因某个协变量 p 值小就认定随机化失败。
5. **MDE 和 Holm 怎么用？** MDE 是预先愿意识别的购买率业务差，不是看到结果后选阈值。样本量结合基线、功效和检验预算计算；两次购买率主比较用 Holm 校正，规划可用 Bonferroni 保守分配 alpha。访问/收入为辅助指标，逐指标两次校正不等于六次比较整体控制。
6. **一年历史消费能做 CUPED 吗？** 它是处理前协变量，可以调整，但与两周结果窗口不同；系数从训练数据学习，不让测试标签参与。是否降方差看实际验证，不能假设相同窗口或保证有效，也不能以历史消费与新结果相减替代增量。
7. **为什么还需要 DR 策略评估？** 预测 CATE 不是真实个体效果。已知各臂概率 1/3，DR 用预测均值加分配一致样本的加权残差，估计固定政策相对不触达的平均收入。随机化支持识别，不需要宣称解决了未知混杂；有限样本模型仍可失误。
8. **证明定向触达更好看哪个区间？** 在验证集选择模型、臂和接触上限，冻结后测试。比较两种政策须对同一用户贡献做差，报告配对差值区间；各自利润区间重叠不是优劣检验。利润情景区间也不证明真实业务盈利，且不覆盖重训/政策选择不确定性。
9. **交易数据清洗最关键是什么？** 一行不是一单；退货需进入净收入，匿名买家不能补 ID。首次观测不是真新客；cohort 起点有左截断，终点有随访不足。完整重复行未必是重复日志，须保留去重假设和金额影响。
10. **你能说熟练 Hive、已经上线吗？** 只按执行证据回答。DuckDB 是本地 SQL 引擎；Spark 启用 Hive 支持不等于 Apache Hive 执行。Hive 要能解释外部表、ORC、分区、动态写入、聚合粒度和运行日志。本项目是独立离线研究；没有真实团队协作、在线实验或部署收益。
